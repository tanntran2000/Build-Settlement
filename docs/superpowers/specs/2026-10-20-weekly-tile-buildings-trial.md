## Workforce assignment clarification — 2026-10-21

Assign workforce once per building: the confirmed `building.workers` remains assigned across End Week → Report → Plan and later weeks until changed by an explicit command or the existing building lifecycle. Workforce is reusable shared capacity, not inventory consumed or charged again each week. Reassigning a building replaces its previous amount; the shared total changes only by new amount minus old amount. Other buildings' assignments do not change. Existing state/dispatcher behavior already satisfies this contract; this clarification does not authorize a replacement workforce mechanism.

The tile editor must show the selected building's confirmed workforce beside its draft. An edited but unapplied value must be labeled as such; only Assign workers applies it, not blur, Enter or End Week. A rejected assignment preserves the committed plan and makes its error visible near that input, with the confirmed amount still clear. Selecting another tile or successfully loading a checkpoint resets the editor to that tile's committed amount and clears stale assignment feedback. End Week/Plan display the retained assignment; no weekly re-entry is needed. Planning checkpoints retain every building's confirmed workers through the unchanged codec/schema; UI drafts and errors are not saved.

Editing the workforce draft clears the previous submission's error and invalid marker. It does not validate or apply the edited value: the confirmed assignment remains unchanged until Assign workers succeeds, and a new invalid submission must report a fresh local error. This also applies when editing back to the confirmed value. The clarification fixes stale draft feedback only; resources, week, dispatcher validation and checkpoint data are unchanged.
