# Correction 10 End Week comparison protocol

The inputs are derived from the exact previous B2 save `b2-3-100npc-roundtrip.json` (SHA-256 `6512ceb7562231ed216a0a258e90d825e9bc39c778a860fc6618a9a2359887f2`). Main uses its native ruleset and omits `household`, which its exact NPC validator rejects. All other state bytes are compared through canonical JSON, including all 100 NPC ids, stats, profiles and histories, the world seed, city, homes, Gold and week. Both run the real `executeCharacterLifeCommand(..., END_WEEK)` from their own checked-out sources. Every invocation starts from the same state. No product instrumentation. Source loading, JSON parsing, validation probes, result checks and save round trip stay outside the measured interval.

Run 12 alternating pairs, AB then BA, serially. Each process starts fresh, runs one first End Week command, then repeats it 20 times for warm samples. Use the same Node binary and installed TypeScript compiler. Record elapsed wall-clock in the harness via `process.hrtime.bigint()`. Report per-process medians and cold ticks, paired differences (B2 minus main), their range, and counts at or above 50 ms.

Use the distribution-free two-sided 96.14% median interval from order statistics 3 and 10 of the 12 paired warm-median differences. A positive lower bound is evidence of a reproducible warm cost. Otherwise compare the positive point estimate with the median absolute change between consecutive same-revision process medians, pooled over both revisions. A point estimate within that observed noise and an interval containing zero supports the run-to-run-noise classification. A larger uncertain shift stays unresolved. The 50 ms budget is unchanged, and first-tick observations are reported separately.
