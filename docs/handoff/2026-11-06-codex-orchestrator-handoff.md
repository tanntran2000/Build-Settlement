## 7. Code quality requirements (what the Builder must meet, what you check)

- **TDD.**
  - Failing tests first, with RED evidence, then GREEN.
  - One commit per task, with the plan's subject and the agent attribution line.
- **Determinism.** No `Math.random`. Use the seeded RNG (`crimeRandom(worldSeed, week)`) with a fixed draw order.
- **State.**
  - Commands are all-or-nothing. A refusal returns its code and message and leaves state deep-equal.
  - Validators reject unknown ids, duplicates, out-of-range values and fractions.
  - Each new ruleset refuses older saves with the existing older-version message. No migration unless a spec says so.
- **Numbers.**
  - Milli units.
  - `trialSafe` for every sum; BigInt where the existing code uses it.
  - Clamp to 0–100. Floor where the spec says floor.
- **TRIAL constants.** Each lives once, in a frozen object in `core/trial/*.ts`. No magic numbers elsewhere.
- **UI.**
  - English copy, exact from the spec.
  - "−" is U+2212, "·" is U+00B7, "→" is U+2192.
  - Every rule shown in the UI comes from the same core function the command uses (e.g. `previewLawVote`), so the preview always equals the result.
  - Accessibility:
    - 44×44 targets;
    - WCAG AA: text ≥ 4.5:1; inactive controls and boundaries ≥ 3:1; focus ≥ 3:1;
    - no horizontal overflow at 320, 375, 1280 or 1600 px.
- **Reports.** Every new report field gets `data-*` parity attributes so `expectReport` can rebuild the report from the DOM. Temporary e2e strips are allowed only for the PR between engine and UI, and must be listed.
- **Files.**
  - UTF-8 without BOM, LF in the index, no mojibake (`Â`, `â€`, `âˆ`).
  - The 200-line file heuristic means split by responsibility, not by count.
  - No new dependency, config, CI, audit, timeout or threshold change.
  - No `.github/` edits. No tracked logs.
- **Budgets.**
  - UI bundle < 200 KB gzip (now ~95 KB JS + 5 KB CSS).
  - Fonts ≤ 150 KB.
  - UI sprites ≤ 200 KB; desk sprites ≤ 100 KB.
- **Tests are never weakened.**
  - No deleted tests. No `toBe` → `toBeGreaterThan` swaps.
  - Expected values change only when they follow from an approved rule. List each change as file:line, old → new, derivation.
- **Risk register.** Add a row for each new risk or flaky test. Mark a row fixed, with its PR, when it is fixed.
