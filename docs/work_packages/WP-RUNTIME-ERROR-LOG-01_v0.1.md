## Outcome and scope

Both daily R1 (`/`) and Weekly (`/?mode=weekly`) expose an English **Error log** panel, outside active-settlement guards. It retains at most five adjacent error groups, oldest to newest, and offers an explicit **Download error log** action. It is a browser diagnostic buffer, independent of game state, saves, CI artifacts and gameplay audit reports.

Exactly eight allowed files:

- `packages/ui/src/error-log.ts`, `packages/ui/src/__tests__/error-log.test.ts`
- `packages/ui/src/ErrorLog.svelte`, `packages/ui/src/main.ts`
- `packages/ui/src/App.svelte`, `packages/ui/src/WeeklyManagement.svelte`
- `tests/e2e/error-log.spec.ts`
- This approved WP document.

No core/simulation, R1/canonical schema, persistence, Farm, migration, CI/config, dependencies/lockfile or global CSS changes. Migration v0.3 remains unapproved and unimplemented.

## Data and privacy contract

The only storage key is `haven.runtime-errors.v1`. The JSON envelope has exact keys `schemaVersion: 1` and `entries`. Each entry has only `timestampUtc`, `lastSeenUtc`, `occurrences`, `appVersion`, `buildId`, `mode`, `clock`, `action`, `kind`, `code`, `message`.

- `appVersion` comes from the UI package version; it is currently `0.1.0`. `buildId` is always null. This does not identify an exact build/commit. Loaded versions are bounded to 64 characters and a numeric major.minor.patch format with optional bounded ASCII prerelease/build suffixes.
- UTC timestamps come from the device clock, not the gameplay clock. They must round-trip through ISO UTC formatting and are bounded to 32 characters. Device clock corrections may move observed timestamps backwards; group ordering follows recording order, not sorting by device time.
- The clock is copied from state before the action. Weekly accepts a positive safe `week`; R1 accepts positive safe day/week/year with the existing day-derived week/year consistency. Invalid/unavailable clocks become null. Global capture uses the latest valid context supplied by the active caller; reload starts with no clock until that caller initializes.
- There is no state snapshot, command/payload, gameplay name/ID, world seed, raw exception/code/message/stack, token, URL, query or fragment in a newly recorded entry. No telemetry/backend or automatic network upload exists. Browser default error reporting is not intercepted or suppressed.
- Every message/kind is generated by the fixed code catalog below. Unknown dispatcher codes become `UNKNOWN_COMMAND_FAILURE`. Loader requires exact keys/enums, canonical timestamps, valid clocks, bounded version, safe positive occurrences, at most five entries and exact catalog message/kind; it reconstructs fresh records rather than merging parsed objects.

| --- | --- | --- |

## Capture and caller behavior

| Boundary | Recorded behavior |
| --- | --- |
| Weekly invalid draft | INVALID_WORKFORCE_INPUT; existing locally constructed form guidance remains |
| Weekly/R1 structured failure | Known code or UNKNOWN_COMMAND_FAILURE; UI/console uses a safe catalog message, never the raw returned message |
| Unexpected caller/dispatcher throw | UNEXPECTED_ACTION_ERROR, without reading the thrown object |
| window error after initialization | UNCAUGHT_ERROR for ErrorEvent only; generic/resource error events excluded |
| unhandledrejection after initialization | UNHANDLED_REJECTION without reading reason or preventing browser defaults |
| Success / ignored Report-phase submit | No error record |

Global listeners register once in the entry module before mount. Caller context is updated initially, before dispatch and after success. Logger failures cannot replace gameplay errors or turn a successful command into failure. No UI rollback is invented: transaction/rollback guarantees remain those of the unchanged dispatcher.

## Retention, storms and storage failures

Consecutive entries dedupe only when mode, normalized clock, action, code and appVersion match. The first timestamp remains; lastSeen and occurrences update. A-B-A remains three groups. Occurrences saturates at MAX_SAFE_INTEGER. Entries and clocks are frozen, and capacity never exceeds five groups.

There is no time-based expiry. The sixth distinct group evicts the oldest; otherwise storage remains until browser/user removal or invalid-log discard. This retention is separate from the three-day CI artifact policy.

The whole stored/exported envelope must be at most **8192 UTF-8 bytes**. Raw string length is checked before parsing; UTF-8 size and schema are also checked. The first storage write is immediate. Subsequent automatic writes are at most once per **1000 ms**, with trailing flush. Pagehide and Download force best-effort flush. A hard crash can lose the pending tail (approximately one second).

Blocked storage access/getItem/setItem, quota errors or failed corrupt-key removal switch to RAM-only with no automatic retries in that tab. Reload creates a new attempt. The UI says **Not saved — this tab only. Download before closing.**

Corrupt/unsupported/oversized storage is discarded, with best-effort removal of only the logger key. Other storage is never deleted. The UI says **Stored error log was invalid and has been discarded.** If removal also fails, both notices apply. Logger/storage/export failures never recursively create entries.

## Export and accessible UI

Download serializes only the normalized RAM envelope, flushes storage best-effort, requests a JSON Blob download named `haven-error-log.json`, and removes the temporary anchor/revokes the object URL after the request. It sends no network request. Failure preserves entries and displays a fixed accessible message. **Download requested** means only that the browser request was made; it does not promise the file was saved.

The panel shows kind/code/message, UTC first/last time, mode/action/clock, occurrences, app version and unavailable build identity. Empty state is **No errors recorded.** Download is disabled while empty. Storage/export failures are accessible alerts; saving/download-request status is accessible. The entry list is not a live region replaying every event in a storm. No focus stealing, editing, clearing or importing control is added.

## Verification and limits

- Unit coverage: fixed catalog/privacy, exact loader schema and byte bounds, five groups/A-B-A/dedupe, 10000-event storm/throttle, counter saturation, clocks, reload, storage getter/getItem/setItem/removeItem/quota, no recursion, Blob/object URL/click export failures and cleanup.
- Browser coverage: both panels/language, real JSON download/filename/MIME/size, pagehide/reload persistence while game resets, action throw/unknown failures in both modes via served-bundle instrumentation only, native and synthetic global error/rejection capture and resource distinction, 10000 events, mode clocks, no log network requests, RAM fallback with unchanged gameplay, corrupt-key isolation, export failure, no active settlement and keyboard access. No production test hooks.
- Required final gates: lint, aggregate typecheck, all unit tests, build, browser smoke, npm audit at moderate. Independent audits at exact candidate SHA are still required.

V1 is **one tab**: there is no multi-tab merge; writes on the same origin can be last-writer-wins. Reload preserves diagnostics only when storage works; the experimental game still resets. Static import failures before initialization, browser crashes, resource loading errors and errors before capture starts are not covered. A fatal render error may prevent the panel from rendering in that session. Stack traces are deliberately excluded because they can contain arbitrary private data and there is no exact build identity.

The assistant cannot inspect a user's localStorage remotely. Only a file the user deliberately shares can be reviewed. Version 0.1.0 does not distinguish builds. This WP does not deploy a demo or implement migration/population changes.
